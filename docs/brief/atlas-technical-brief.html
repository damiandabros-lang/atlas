ATLAS — Network Service Orchestration Platform

Technical brief prepared for the DriveNets “Senior Python Engineer — Network Orchestration” review

Author Damian Dąbroś · CCIE R&S #40482 Repository github.com/damiandabros-lang/atlas (public, MIT) Date 19 October 2026

ATLAS provisions, verifies, reconciles and decommissions MPLS L3VPN services across a service-provider core. An operator submits a request through a REST API; a durable Temporal workflow allocates resources, renders vendor-specific configuration, pushes it to each PE router, verifies BGP/VRF/interface state and connectivity, and commits the service — or, when a device fails part-way, runs a Saga-style compensation that restores every touched router and releases the resources. It was designed and built as a production-shaped system (API, database, workflow engine, adapters, observability, Kubernetes packaging, CI), not as a script.

Key design decisions (ADRs in repo)

  • Temporal owns execution state, PostgreSQL owns business state. No workflow state in the DB, no business data in workflow history.
  • Saga over distributed transactions. Three routers are never one atomic commit; every device write is a ledger row with an idempotency key, so retries never double-apply and compensation knows exactly what to undo.
  • Resource uniqueness is a data invariant — enforced by the database, not by a lock or Redis.
  • Reconciliation is DETECT_ONLY by default; automatic remediation requires explicit authorisation.
  • Adapters are the only place that talks to devices; swapping mock → NETCONF is configuration.

Provisioning workflow and recovery

REQUESTED → VALIDATING → ALLOCATING → (generate configs, pre-deployment validation)
          → PROVISIONING: PE1 ✓ → PE2 ✓ → PE3 ✗ (ConfigurationRejected, permanent)
          → ROLLING_BACK: rollback PE2 ✓ → rollback PE1 ✓ → release RD/RT/VLAN/subnets
          → ROLLED_BACK   (audit: COMPENSATION_EXECUTED ×2, RESOURCES_RELEASED)
Transient failure (TIMEOUT_ON_PE2)  → retried with backoff → … → VERIFYING → ACTIVE
Partial apply (UNKNOWN)             → inspect device state → continue or compensate
Compensation itself fails           → MANUAL_INTERVENTION_REQUIRED (nothing hidden)

4. What I would do next (and can discuss in depth)

  • Point the IOS XR adapter at containerlab / XRd and replace the mock in the e2e suite with real NETCONF (candidate + commit-confirmed, rollback by commit id).
  • Second service type (EVPN / L2VPN) to prove the domain model and workflow generalise; Temporal child workflows per device for parallel provisioning with per-site failure domains.
  • AUTO_REMEDIATE behind an explicit approval signal; OIDC instead of API keys; Temporal Cloud + managed PostgreSQL values for production.
  • Telemetry-driven verification (gNMI subscriptions) instead of polling, feeding the same reconciliation engine.
