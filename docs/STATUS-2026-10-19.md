## Błąd wykryty i naprawiony przez e2e
Przy anulowaniu workflow w trakcie zapisu na PE1 aktywność czekała na dokończenie zapisu (żeby urządzenie było w znanym stanie), ale nie zapisywała wyniku do ledgera → kompensacja pomijała PE1 i VRF zostawał na routerze. Naprawione: `CancelledAfterSettled` w `atlas/activities/_support.py` niesie wynik zapisu, `provision_device` zapisuje SUCCEEDED do ledgera i dopiero wtedy propaguje anulowanie.

## Jak uruchomić u siebie
```bash
cd atlas
docker compose up -d --build       # Postgres, Temporal (+UI :8080), API :8000, worker, Prometheus :9091, Grafana :3000
./scripts/demo.sh                  # ACME L3VPN na PE1–PE3 → ACTIVE, historia, reconcile
ATLAS_MOCK_FAILURE_MODE=FAIL_ON_PE3 make demo-fail    # kompensacja → ROLLED_BACK
make install && make test          # 172 testów lokalnie (Python 3.12+)
```
